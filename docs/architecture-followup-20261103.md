## 更大的设计缺口

1. **运行事实缺少一致的来源。** 工单、当前 Dispatch、终端、报告和通知存在多份状态；现在既能旧回执覆盖新执行，也能拿旧终端解释新执行。应先以原生当前 Task/Dispatch 和持久尝试记录对账，再输出状态，并附证据时间。
2. **存活不代表推进。** ready、连接存在、历史 progress 都不能证明当前有工作。“当前执行是否存在”“最新进展何时产生”“未完成义务由谁接手”需要分别展示；未知不得显示成正在推进。
3. **唤醒不代表目标有人继续负责。** watcher 能把 Router 叫醒，却不保证它更新范围、处理用户补充、接续授权内下一步。多次诊断后停在“等下一步”，或问用户重新批准已经授权的工作，仍是控制流程缺口。真实的数据缺失、权限边界则必须保留，不能为了持续推进强行绕过。
4. **组合故障未被测试覆盖。** 现有单项恢复/通知/结算测试不足以证明初始启动不确定、恢复、旧作业重放、服务重启与报告失败连起来仍正确。

修复顺序：先阻止身份回退并对账现有分叉；随后保证报告断线可补交；再把状态汇报和授权内接续绑定到当前证据及未完成义务。无需先引入新框架或更多监督代理。

本报告是对上一轮交付记录的补充与纠正。上一轮修复已覆盖的消息登记、范围更新和通知问题仍有价值，但不足以宣告持续推进问题已经解决。尚未逐个业务目标验收，也未对真实任务再次重试。
