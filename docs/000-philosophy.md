# 000 理念

状态：2026-11-06，确定第一版产品定位、结构和主要交互；不代表现有实现已经达到要求。

对应上游：[000 Philosophy](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/000-philosophy.md)。沿用其章节顺序，将团队单仓库的使用方式调整为个人多项目协作。职责边界遵循 [OSA 开发宪章](../AGENTS.md)。

OSA 面向一个同时推进多个项目的人，连接不同智能体和窗口中的工作。它的核心理念是：

**以尽量少的所有者注意力，持续完成多个项目中需求、执行、反馈和决策的循环。**

所有者不必记住每个窗口做到哪里，也不必反复搬运结果、寻找执行者和催促继续。工作应有明确的归属，结果能回来，决定能送达，后续要求能接上已有成果。

## 对智能体意味着什么

对应上游：What follows for the agent。

- **一个 Router 面向多个项目。** Router 澄清结果和项目，定位并路由请求，传达执行者的结果与问题。它可以查看相关项目状态，但不能因此获得修改项目或决定技术方案的权限。
- **执行者负责具体工作。** Executor 在任务授权内规划、探索、实现和验证，可调用其他智能体协作。普通技术摩擦自行解决；需求前提不成立时，说明依据并交回。
- **反馈回到对应任务。** 所有者的要求、补充、决定和 Agent 的回复保留在同一件工作中。换窗口或换执行者后，已有目标、成果和待决事项仍可读取。
- **有用时再打扰所有者。** 普通进度更新到任务；有可用结果、需要决定或确实无法继续时，主动带回。每次提出具体问题，说明影响，已有授权不重复确认。
- **状态如实表达。** 区分已收到、正在处理、等待、失败和完成。未核实的状态保持未知，不能用窗口活跃、消息送达或测试数量代替业务结果。
- **尊重所有者的控制。** 所有者可以直接进入任意执行窗口交流。明确停止的工作保持停止，新的通知或服务重启不构成恢复授权。

## 对产品设计意味着什么

对应上游：What follows for the design。

第一版确定以下结构：

| 决定 | 第一版选择 |
| --- | --- |
| 使用者 | 一个管理多个开发项目的所有者 |
| 路由 | OSA 一个跨项目 Router；各项目分别保存上下文 |
| 主入口 | 按项目组织的任务列表／项目管理表 |
| 任务交互 | 在任务内评论、提要求、回答问题、查看 Agent 回复 |
| 辅助入口 | 全局聊天用于查询和提出请求；飞书、GitHub 可按需接入 |
| 执行 | 复用 Orca 及已有智能体窗口，支持多个执行者协作和接替 |

**任务表保存持续工作。** 项目下创建任务，任务内持续讨论。所有者用自然语言表达要求，系统和 Agent 维护进展及关联，不要求所有者手工整理每个步骤。

**全局先呈现需要人的事项。** 汇集待决定问题、待查看结果和异常停滞，再提供正常工作的摘要。项目页展示本项目的任务；任务页展示要求、进展、对话、产物和对应执行窗口。

**聊天与列表使用同一份工作记录。** 在任务内补充要求时，归属已经明确；全局请求由 Router 定位。有歧义才询问，不凭主题相似把工作混在一起。一个项目不必对应一个飞书群，也不必只包含一个仓库。

**直接打开的窗口也能关联工作。** 所有者可以从 OSA 发起，也可以先在 Codex、Claude 等窗口开展工作，再关联到对应任务。关联不明确时确认，关联本身不扩大原授权。

**权限随任务范围确定。** Router 的跨项目可见性用于路由；Executor 的行动依据来自具体任务。Agent 的进度更新和评论不会自行产生新的授权。

**保持产品简单。** 复用 DeepSeek 的领域思想和 Orca 的执行能力。新增规则、配置或流程必须解决真实问题。一个逻辑 Router 不预先规定会话、进程或服务实例数量；界面的具体接入方式留到后续章节验证。

**从实际需要决定实现。** dsh 和旧 OSA 都是参考，不是必须复制的清单。已确认的目标、实际使用和可复现问题决定要做什么。没有反例的低概率边界或并发问题，先说明触发条件、发生概率的依据和改动代价，取得所有者确认后再加机制；没有数据就写概率未知，不凭“理论上更稳”扩展代码。

**实现保持直接。** 外部数据在明确入口校验一次，内部使用类型和既定业务规则。单次使用的逻辑就近写清楚，不提前建 helper、注册框架或包装层。只有当前层确实能恢复、补充错误信息或释放资源时才用 `try/catch`，否则交给已有错误出口处理。

**文档按顺序说明。** 第一章确定理念；后续逐章明确领域、授权、执行、提示词、面板、部署、架构和扩展。实现缺口单独说明，不把设计目标写成已有能力。

## 责任

对应上游：Responsibility。

所有者决定目标、业务取舍和授权范围。删除、推送、改线上及对外发布需要相应授权；同一范围已经明确授权的，不反复询问。

OSA 负责维护工作归属、反馈去向和可追溯记录。执行者负责工作和交接，如实说明结果与限制。Router 不改写需求，也不弱化执行者的拒绝或分歧。

这是同机、同用户的个人工具。可靠性要求是不静默丢失、异常可发现、必要时能由人恢复。规则和异常处理本身也要减少人的负担。

判断产品是否有效，看交付的结果、工作能否接续，以及所有者为记忆、查找、协调和催促付出了多少注意力。
