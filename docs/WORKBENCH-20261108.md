# OSA 独立任务工作台：目标与实施前核验

2026-11-08。承接本轮所有者确认及两张界面参考。代码基线 `a178882`。已核验宿主呈现、DSH 权限和历史范围，并按所有者选择实现主区域标签页。业务改动和测试仅在隔离状态验收，未切换正式服务。

## 已对齐的目标

在 Orca 中提出和查看日常开发任务。主工作区采用浅色、紧凑的任务行和左右两栏；窄侧栏保留配置及快捷入口。保留 DSH 的话题、Router 判断、不可变授权及交回规则。

- 日期、项目、工作树三种视图；项目内再按日期组织，支持搜索和筛选。
- 项目当天清单可直接提出要求；项目提供上下文，原话先保存，再由 Router 判断。Router 可以说明理由后路由到其他项目，原始入口仍指向同一话题；明确指定项目的原话仍须遵守。Router 聊天入口继续可用。
- 提出当天保留入口，后续有实际交流或进展的日期出现活动；各日期指向同一个持久任务话题，不复制工单。
- 任务详情按时间展示已记录的人、Router、执行者交流与结果，可继续补充或回答。
- 工作树、执行窗口与成果根据实际关联显示；未知归属、读取失败、记录缺口明确说明。
- 原配置和任务数据继续可用；不修改 Orca 本体、patches 或 vendor。

完整验收范围沿用所有者本轮列出的七项，不以单元测试或示意图代替实际操作。

## 独立窗口核验

本机运行 Orca **1.4.253**。读取该版本自带的插件 manifest、Host API、CLI 指南、`plugin open --help` 和全部 321 个 CLI 命令的 schema。

| 公开能力 | 当前可证实的呈现 |
| --- | --- |
| `contributes.panels` | 右侧栏面板 |
| `contributes.customEditors` | 打开文件的主区域自定义编辑器标签页 |
| `plugin open --panel` | 显示右侧栏 |
| `plugin open --editor`、`editor.open` | 打开对应编辑器标签页 |
| Host API／命令 schema | 未提供插件创建独立原生窗口或脱离面板窗口的入口 |

因此，目前不能承诺用公开接口复现“智能体仪表盘”那种独立原生窗口。内置仪表盘拥有窗口，不证明第三方插件也拥有同一接口；截图命令的 `--window` 是捕获窗口，不是创建窗口。

证据保存于 `.osa/workbench-preflight-20261108/`：`status.json`、`manifest.md`、`host-api.md`、`cli.md`、`plugin-open.txt`、`agent-context.json`。其中 manifest 第 36、47、54–62 行与 CLI open 帮助直接声明了呈现位置。

**呈现已确认：2026-11-08 所有者选择方案 1。以下备选仅保留核验依据。**

1. Orca 主区域工作台：使用公开自定义编辑器标签页承载完整布局，侧栏保留入口；它是标签页，不是独立 OS 窗口。优先推荐，改动较少，仍在 Orca 内。
2. 独立网页窗口：从 Orca 打开本机网页，由浏览器承载窗口。需新增本机网页入口，窗口不属于 Orca；选定后再验证具体启动及连接方式。
3. 保留独立原生窗口要求：等待 Orca 增加公开接口，不擅自用另一种呈现代替。

已获准实施主区域自定义编辑器标签页；不再等待窗口形式确认。窄侧栏保留配置和打开工作台的快捷入口。

## DSH 的“最高权限”

参考版本仍为已有的 `8c32a9dc5d72`，不宣称核验了上游最新 HEAD。

- `src/app/sessions.ts:152` 为 Router 和 Executor 会话设置 `danger-full-access`。原版部署文档第 19 行明确：以操作者 OS 用户运行，账号包装器不构成隔离。
- `sessions.ts:244` 仍向执行者注入 Mandate；第 263 行限制 Router 工具，第 289–295 行按工单状态限制工作工具。环境权限不替代工作授权。
- 原版 `002-authorization.md:20`：已订阅消息作为上下文投递，不增加授权。第 38 行：所有者可以从面板把执行者负责的补充送回评估；这不同于 Router 自行抢走消息。
- `prompts/work.md` 默认在已有授权内完成实现、提交、推送和 PR 交付。`prompts/team/delivery.md:9–16` 仍要求按约定审查；未指定合并 CLI 时人工合并，指定后仍受当前提交批准等条件约束。没有由 full-access 推导出的无限生产部署授权。

OSA 延续已确认的规则：授权可以来自本次原话或已确定的项目约定，不逐动作重复询问；新增范围仍须处理。实施本工作台不自动修改 Orca 全局 Agent 权限或启用无条件合并、部署。

**本轮已对齐的三处：**

1. `src/orca.ts` 提示词允许复用所有者请求和已确认项目交付约定，不再要求每次 ticket 重列步骤；不凭空创造项目授权。
2. `src/app.ts` 的所有者重新评估复用核心人工接口；Router 仍不能自行抢走执行者负责的输入。
3. `src/feishu.ts` 保留订阅话题中其他人和机器人的身份及反馈，新工作继续受 owner-only Gate 约束。

这些改动已补回归，没有扩大现有业务授权。

## 记录能展示到哪里

| 记录 | 已有依据 | 不应声称 |
| --- | --- | --- |
| 人的要求与补充 | 实际进入 panel、Router intake 或外部来源的 Trigger | 所有普通聊天都已经登记 |
| Router 判断 | `core.decision`、已发送回复、派发记录和回执 | Router 的完整逐字会话或内部推理 |
| Executor 进展与结果 | `report-receipt`、assignment 报告、信箱消息 | 未上报的动作或聊天已被完整收录 |
| 外部回复 | outbox 及新记录的 createdAt | 旧记录缺失的发送时间可以补猜 |
| 已关联结构化窗口 | 公开 `agentSession.history` 按需观察 | 一次 tail 查询就是完整历史 |
| 终端窗口 | 原生屏幕观察 | 终端屏幕等于完整对话历史 |

对当前本会话做了只读查询 `direction: tail, limit: 20`：返回 `hasOlder=true`、有 nextCursor、10 个 item 标记 shortened。一次请求返回 45 个 item，因此 limit 也不能简单当作“完整的 20 条聊天消息”。仅保存覆盖标记，不保存本次聊天内容；见 `history-observation.json`。

工作台应标注“已记录的交流”，展示来源与缺口。现阶段不重建原生输入流留存，不读取 Orca 私有库来补完整历史。

## 呈现确定后的实现顺序

1. 复用当前 API、话题、工单、原文、报告和草稿；增加日期／项目／工作树的查询投影。日期只是视图，不进入工单身份。
2. 当天按所有者本机时区组织。提出日使用已存原请求时间；活动日使用真实消息、判断、报告时间。轮询 observedAt 不产生每日活动；缺失时间放到“时间未知”，不猜到某天。
3. 单一话题可出现在多个日期；提交前的请求在接单后连接已有 ticket，不保留两份任务。计数区分唯一任务与日期活动条目。
4. 按已确认参考制作紧凑列表、分组切换、搜索筛选和右侧连续记录，保留原配置快捷入口。关联不明的工作树单独显示，不根据标题猜归属。
5. 对齐已发现的权限差异，同步提示词、接口和测试；不引入新的授权平台。
6. 用两天的实际时间记录验证同一话题、多项目隔离、查询回复、任务补充、成果与窗口关联、重开后草稿和旧数据兼容；实际页面操作和截图最后验收。

当前状态：主区域工作台、原有侧栏配置／快捷入口、日期投影与话题续接已实现。验收结果见 [工作台验证](WORKBENCH-VALIDATION-20261108.md)。正式服务和远端未变更。
