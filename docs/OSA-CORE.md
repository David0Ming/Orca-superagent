## 已确认的共同约定

- 面向一个管理多个开发项目的所有者；一个跨项目 Router 负责定位、路由和反馈，Executor 负责规划与实施。
- 项目按业务归属组织，可包含多个仓库。仓库数量不增加特殊权限，不强制增加组件管理层。
- 项目任务表是主入口，任务内评论连接人的要求与 Agent 的回复；聊天、飞书和 GitHub 可以接入同一工作。
- 优先沿用原版 dsh 的接单、订阅、不可变授权、交回和交付规则。普通补充继续原工作，范围外请求重新接单。
- 复用 Orca 的执行、窗口、工作区和原生消息能力。重启 OSA 不推断 Agent 已退出，不重复派工。

## 实现与验证边界

首选部署是 Orca 插件面板连接一套本机 OSA 服务和状态库，多项目共用。公开接口和既有代码提供了基础，仍需验证：

- 插件与服务的真实读写、面板操作身份以及不抢占 Router 的查询入口。
- 项目任务评论、Router 后台唤醒、执行者处理和原处交付的完整循环。
- 已有窗口的人工输入与工作结果如何持续关联，草稿如何保持完整。
- 多仓库目标与现有工单、执行位置和发布接口的映射。
- 人工停止、提示词生效及旧版门禁是否符合实际工作需要。账号先使用适用的现有配置，专用账号不是默认前置条件。

文中已区分“沿用”“适配”“现状差异”和“待验证”。旧代码、旧测试和历史设计用于对照，不因存在就成为新版规范。具体旧业务故障证据见 [需求复核](stall-repair-20261104.md)。
