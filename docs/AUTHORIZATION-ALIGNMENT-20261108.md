# 移除 OSA 额外门槛

所有者批准：默认沿用 DSH 授权与执行语义，只保留 Orca 公开能力所需适配；不新增权限分类器、依赖扫描器或启发式门禁。

## 依据与改动

原版依据为文档固定版本 `8c32a9d` 的 `docs/002-authorization.md`、`docs/003-execution.md` 和 `prompts/team/scope.md`；本地核心仍是 `6337fc8`，未修改。

| 原版原则 | 删除的 OSA 差异 | 保留的适配 |
| --- | --- | --- |
| 目录不是权限边界，授权来自 Mandate 与项目规则 | inspect 自动只读禁令 | 旧参数兼容、注册目录身份核对；所有者明确只读仍有效 |
| 执行者按授权完成工作 | 续用目录禁止发布、终端非空禁止续接 | 原生执行身份与未结束资源核对；续接继承原目录模式 |
| 交付规则约束执行者，不由 Router 另授权限 | publish 开关门禁、旧发布授权迁移门禁 | 旧记录仅用于历史展示；发布辅助工具仍核对账号、仓库、分支和 PR |
| 报告与真实 PR 状态共同表达交付 | ready 必须有 OSA 专有发布回执 | 保留已绑定 PR 跟踪；多仓当前工作尚未 ready 时不以历史 PR 结束它 |
| 已读后续由执行者处理，未读后续可释放回评估 | ready 前必须再次读取完全相同快照、强制逐项 --inputs | read 返回真实输入并调用核心送达／已读 API；核心报告处理释放。旧 --inputs 可选兼容 |
| 没有默认自动删工作树闭环 | 文本提到目录即保留、基线变化即保留、每小时空引用证明 | 仅明确请求下非强制调用原生删除；保留真实目标、脏文件、未结束任务及已保留资源检查 |

原生 `worktree rm` 文档说明当前版本默认保留本地分支，`--delete-branch` 才另行请求安全删除。本辅助工具不传 `--force` 或 `--delete-branch`。没有根据文件名猜依赖，也没有添加提交合并判定器。

## 旧任务接续

Orca `worker-start --retry-of` 复用原 Task，公开 `task-update` 仅更新状态／结果，不能改派发 spec。保留同一任务和真实尝试记录；当前 `read` 协议说明旧 OSA 生成的 inspect 禁令已撤回，原所有者及项目限制仍有效。不得把这项服务纠正写成所有者的新业务要求。
