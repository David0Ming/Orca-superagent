# 009 状态守望：让等待中的事有人看

状态：2026-11-13，已实现（见文末实现记录）。依据所有者当日的只读状态审计，以及 dsh-superagent-prototype、agent-autoloop 两个项目的对应机制。

## 一、要解决的问题

审计的结论：系统没有结构性漏洞。会写坏的动作都被 Orca 原生的绑定围栏拦住（票只能由绑定该 Run 的会话改），其余靠提示词自律。真正薄的一环是**等待中的票可能永远没人看**——这个坑之前叫"等待条件未注明"，现在叫"等外部事件"，同一个形状。

分三层看：

```
硬约束（Orca 原生，模型绕不过）
  绑定围栏、消息类型、派发监督、状态枚举、失败启动熔断
软规定（脚本与提示词，靠模型自觉）
  osa-router 技能、executor-rules、预检分类、定时任务、osa-team.sh 引导语
展示层（面板代码，只读）
  分区、颜色、条件显示
```

问题都出在软规定层，且都是"形式对了、内容没人盯"。

## 三、两个项目的对应机制

两个项目对"等待中的事被遗忘"的答案都不是再叮嘱模型，而是**给等待装一个钟**：

| 机制 | dsh-superagent-prototype | agent-autoloop |
| --- | --- | --- |
| 等待有截止/复查时间 | 评估有 deadline，过期自动重评，三次后转 unavailable（`src/core/evals.ts`） | 执行者交回时可带「later」预约复查时间，到点由时钟重新入队（`protocol/validate.ts`、`kernel/decide.ts` 的 tick） |
| 扫描"安静太久"的东西 | 中断的派发先看最新报告是不是等待/受阻，是则不无脑复活（`src/core/assignments.ts`） | tick 末尾扫一切安静太久的事项（`kernel/decide.ts` 的 sweep） |
| 提醒节奏 | — | 未答卡片按 0/1/3/7/15…分钟递增重发（`kernel/decide.ts` 的 RESEND_AT） |
| 宿主/协调者失联 | — | 中台失联几分钟就通过外部命令喊人（`worker/worker.ts` 的 watchHub） |
| 格式/规则换代的退出 | 策略版本变化时显式触发（`policyChanged`） | 规则文件带版本，解析时校验 |

共性：等待是**带时钟的事实**，不是提示词里的一句叮嘱；到点由程序把事实摆到协调者面前，判断仍由模型做。

## 四、方案

### 4.1 pending 写复查条款（问题 1）

Router 把票置 pending 时，在同一次 `task-update` 里写清复查时间与依据：

```
task-update --id <id> --status pending --result "复查：2026-11-20；依据：上游发布"
```

- 位置与 blocked 的「问题：」同构，都在原生 result，扫描器只读原生，不读缓存。
- 没有「复查：」的 pending 视为未注明，和 blocked 没写问题同样处理。
- 日期到了**只提醒，不自动改状态**。Router 看到后二选一：解除（置 ready 派发）或续期（改日期）。模型判断，扫描器只报事实。
- 若实测发现原生不允许改 pending 票的 result，退回按票记在 Run 状态文件；result 仍是首选。

### 4.2 扫描增加三类检查（问题 1、1 的派发盲区）

`queue-scan.sh` 在原有形式检查之外增加：

| 检查 | 判定 | 说明 |
| --- | --- | --- |
| 复查钟 | pending 缺「复查：」→ 上榜；复查日期已过 → 上榜并注明 | 不动状态，只列事实 |
| 执行者死活 | dispatched 但关联执行者不在（存活判定不是 live）→ 上榜 | 用 `worker-list --run <RUN> --full`，面板已在用；加宽限（如 10 分钟）避免"刚派发还没起来"误报 |
| 提醒年龄 | 每行附"已挂起 N 天"（按票的更新时间） | 不加计数器，不引入额外状态 |

### 4.3 旧口径与缓存清理（问题 2、3）

- `osa-team.sh` 恢复窗口时注入的说明改为新口径：blocked 必须写「问题：」；pending 必须写「复查：」；状态文件只是缓存，原生 result 才是依据。
- 删除切换缓存里的旧等待键。不为缓存造失效机制。

### 4.4 过渡格式的退出日（问题 4）

脚本顶部一个常量：

```
LEGACY_CUTOFF=2026-12-01   # 日期待所有者定
```

过了这天，旧格式「等待：…；解除：…」不再算已注明，旧票按"未写复查条款"上榜，并提示换成新格式。

### 4.5 面板只读归并（问题 6）

无绑定 Run 的票，不论什么状态都不进"需要你/待开始/等待外部事件/进行中"，只进折叠的历史区。这是显示层调整，不改任何数据，不扩 Router 范围。展开详情里对 pending 加一句说明："原生 pending，本系统读作等外部事件"（问题 5）。

### 4.6 Router 无绑定时的提醒（问题 7，可选）

预检里判断该 Run 当前是否还有活的协调者，没有就把提醒正文改成"本 Run 无绑定会话，需要 resume <名字>"。

检测方式待实测：自动化脚本里 `run-current` 看到的绑定可能不是 Router 窗口。若拿不到可靠信号，改为由面板显示（面板能读到绑定信息），脚本不做这件事。

## 五、不引入的东西

- dsh 的效果队列、工单状态机：宪章明确不要，审计也确认无结构性漏洞。
- autoloop 的租约自动重排：会绕过 Router 判断，且 Orca 已有三次启动失败熔断。
- 事件溯源、hub、卡片通道：自建中台的组成部分。
- Orca 原生决策门（gate）：能当"等人决定"的硬对象，但当前 blocked 已够用，没有真实反例，暂不引入。
- 任何缓存失效框架、提醒计数器、自动状态推进。

## 六、建议顺序与验证

1. 两处一行修复（osa-team.sh 口径、缓存键）——零风险。
2. pending 复查条款与扫描复查钟——治根。
3. 执行者死活检查与提醒年龄。
4. 面板死 Run 归并。
5. 旧格式截止日。

验证方式：每条都用真实数据走一遍。造一张 pending 票（测试 Run），跑一次预检看清单是否点名；改引导语后 resume 一次看注入文字；面板用现有模拟 CLI 的测试与截图工具看分区。不以理论竞态作为阻断，按宪章以真实复现为准。
