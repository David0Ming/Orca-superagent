## 已实现

- Router 聊天 ID 只用作回复地址，新请求单独路由，补充显式 attach；保留旧输入重放身份，不改上游 dsh-core 或 GitHub/飞书订阅语义。
- `route attach --scope` 记录所有者消息、旧范围和新范围，当前范围替代旧派工约束；审查原有指纹会因范围改变失效。
- `read` 保存读到的范围与输入集合；`report ready` 拒绝过期读取及未记载处理结果的人工补充。`report --inputs` 与只表示已读的 `ack` 分离。
- 按工单发送进展；无人工问题的 waiting 五分钟后仍未推进会再次提醒。新增 status.taskProgress 区分业务报告、执行状态、待处理输入、排队原因和交接记录。
- 结算对账核对 Task/Dispatch/Run、当前派工及真正 worker_report。执行者误绑定服务 Run 的情况，仅在其结算且子资源已结束后恢复服务消费。其他协调者归属冲突继续保留。
- 迟到输入不再反复发送给已结束的 Dispatch；安全结算回收后续派。没有 worker_report 但已明确退出的 stopped/abandoned 执行可以释放容量，保留业务目标，产生显式恢复通知，不自动重跑未知动作。
- 本地 fleet 缺状态或不支持能力时，可使用精确本机执行观察的退出证明；远程失联、普通未知及身份不匹配仍不得释放。
- 单工单恢复不再等待无关执行通道。原生收尾也会核验子任务资源。
- 看门狗事件身份不再含十五分钟时间桶；相同待办最多每五分钟重复提醒，观察时间变化不制造新事件。
- Router skill 改为确认唯一持久监督责任方，不再给已由服务覆盖的任务手工重挂 /tmp watcher。保留独立推进、即时汇报及授权内继续的要求。
- 发现并修复托管器缓存旧启动参数的问题：每次启动重新验证并读取配置；托管身份路径固定，避免静默换状态目录。当前运行参数已核实为六槽、gpt-6.1-terra。
- npm test 排除 `.osa` 中的外部项目证据源码，避免把 Node test 文件误作为 Vitest 套件执行。
