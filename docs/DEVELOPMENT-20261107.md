# OSA 开发计划

2026-11-07。所有者要求先写计划，然后连续完成开发，最后统一验收。

依据：`AGENTS.md`、`000–008` 产品文档及本次旧版审查。历史 P0–P4 计划只作参考。当前基线为 365 项测试和类型检查通过；已有测试不替代新版行为验收。

## 交付目标

一个人通过 Orca 内的项目任务表管理多个项目。提交要求、补充和答复后，原文持久保存，Router 定位与路由，Executor 推进，结果回到原任务。项目可以包含多个仓库，任务可以涉及多个仓库；业务状态、执行状态和消息处理状态分别显示。

复用现有 dsh 核心、SQLite、Orca 执行适配和来源。只实现本轮确实需要的界面与连接，不另建调度器、数据库、团队权限或提示词平台。不改 Orca 本体、vendor、既有 patches；不恢复已放弃的可靠性路线。

## 实施顺序

### 0. 保存基线

- 将现有源码、测试和文档建立本地 Git 基线；忽略状态库、凭据、依赖与临时产物。
- 后续按完整主题提交。本轮不推送远端、不部署生产、不恢复历史已停止的业务任务。

### 1. 修正旧流程

- 已结算子任务保留窗口时，不再仅因 `retained` 堵住父任务接续；仍有实际编辑执行或状态不明时保留明确原因。
- 去掉固定 Codex/Claude 组合、通用强制审查与两轮上限。任务和仓库明确要求的审查由 Executor 执行并报告；发布保留原授权、正确目标和提交检查。
- `attach` 只增加 Input，不改原 Mandate；范围外请求沿用交回与重新接单。
- GitHub 已订阅讨论接收其他人和机器人的反馈；是否可以新建工作仍由既有 Policy 判断。
- 发布任务不再自动进入无法发布的续用工作区；显式不兼容选择在入口说明。
- 同步改调用点、提示词、测试和运行说明，保留已有 retry 与报告回执修复。

完成标准：审查中的五个阻断用例改为验证正确行为；旧回归继续通过。

### 2. 接通所有者入口与通知

- 查询状态不领取、不续租 Router 控制权。
- 所有者的项目登记、请求、任务评论和停止操作通过明确的本机接口进入现有服务；不允许把界面提交冒充 Executor 报告。
- 原文、项目归属、投递/读取/处理事实及 Agent 回复可查。重复提交使用同一消息身份；后台刷新保留草稿。
- 普通进度留在任务记录，结果、问题和需要处理的异常才进入提醒。Router 处理当前事件后让出轮次。
- 人工停止 OSA 时，既有托管器尊重停止意图；人工启动恢复托管运行。

完成标准：只读操作不影响 Router；新请求与任务评论均持久保存；通知安静且待处理信息不丢；人工停止不会自动反弹。

### 3. 适配多仓库与已有窗口

- 保留旧单仓数据可读；在现有目标记录上表达同一任务的相关仓库，组件不作为必填产品层级。
- 一个负责的 Executor 获取各仓库准确位置与工作区，按需组织子任务；发布及成果逐仓记录，不能用其中一个 PR 的关闭冒充整体完成。
- 通过公开 Orca 接口提供窗口定位与显式关联；关联本身不扩大授权，也不启动重复执行。
- 核验原窗口的输入/结果接口。若当前宿主不提供完整能力，明确显示能关联什么、哪些消息未接入，保留可用的任务内评论路径，不修改宿主补接口。

完成标准：两个项目不串数据；同一任务能在两个临时仓库产出并汇总结果；旧单仓任务仍能读取和继续。

### 4. 制作 Orca 插件面板

- 先核对当前 Orca 的公开插件模板与通信，再选择最少代码的原生接入。
- 全局待处理视图、项目任务表、任务详情与持续对话；可查结果、原要求、相关仓库和执行窗口。
- 支持项目/仓库登记、提出请求、补充和回答、搜索；停止和重试只连接实际可用的服务动作。
- 设置显示实际服务、来源、Router 和执行配置；缺配置、离线、失败和空列表分别说明。
- 沿用宿主视觉与组件；键盘可操作，刷新不破坏草稿。不添加新的前端框架或服务器，除非原生接口确实要求。

完成标准：插件校验通过，真实面板可操作，状态来自服务，提交失败保留草稿并说明原因。

### 5. 集成验证与交付

- 运行类型检查及完整回归；新增测试只覆盖改动涉及的真实行为。
- 在隔离状态和临时目标验证：提出请求 → 路由 → 执行 → 补充/答复 → 原处结果；两项目、多仓库、已结束执行接收补充、重启不重复派工。
- 使用真实 Orca 插件与临时 Agent 验证公开接口；不向业务群发送测试消息，不发布真实 PR，不影响正在运行的正式 OSA。
- 更新安装/启停说明、九章的实现状态及验收记录；保存本轮集成提交，列明实测通过与宿主限制，供所有者统一验收。
