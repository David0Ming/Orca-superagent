# OSA 会话面板

读取 Orca 原生 Run、任务、Dispatch、消息和执行记录。侧栏使用 Orca components API；Run 是 Router 收件箱，task 是工单，ctx/Dispatch 是一次执行尝试。调度仍由 Orca 原生编排负责。

- 范围：当前工作区、项目、全部 OSA Run。无法从当前窗口识别工作区时可手动选择。
- 搜索已载入 Run 的任务原文、结果及最近消息；列表仅返回摘要，展开标题默认只读最近一轮（最后用户输入及后续智能体文字回复，不含工具批量输出），缺少用户输入时标明不完整；执行者最近一轮、执行历史、Router/Executor 往来消息分别提供查看/收起；历史与最近一轮互斥，往来消息按需展开，收起任务标题会重置内部展开状态。默认读取最近 20 个 Run，可加载更早的 Run；原生 Run 分页每次不超过 100 条，按游标读到请求数量。
- 筛选：智能体、状态；分组：Run、项目、工作区、智能体；排序：最后更新、标题。
- 分区按“该行在等谁”：需要你（活跃 Run 的 failed 工单、所有 blocked 工单、每个 Run 的未回复 question/escalation 聚合为一条“有消息待回”；消息不复活 Run）；待开始（ready，可派发）；等外部事件（pending，等发布、平台恢复或依赖满足）；进行中（dispatched 或关联执行者在线，failed 与等待状态优先）。completed/succeeded/success/done 始终隐藏，活跃分组仅显示已完成数量。颜色按等谁编码：红=出了问题或待回话，橙=等你决定（blocked），绿=等派发（ready），灰=等外部事件（pending），蓝=执行中。
- Run 仅由在线执行者或原生 pending/ready/dispatched 任务维持活跃，消息不参与。先按工单分类：blocked 始终留在“需要你”（含静默 Run 的票，标注无 Router 可处理）；死 Run 的 failed、其他非活动工单及待处理消息进入底部“历史”，默认折叠；空分区不显示标题。blocked 只表示“有人必须动手”：副标题展示原生 deps 及 result 里“问题：…”的那一句，不从 spec、标题或状态文件推断；等外部事件的票是 pending，不占 blocked。没写问题就明确显示“受阻但未写明要你决定什么”并附原文前 120 字。
- 行内 `@` 单击等待 300ms 后复制任务编号及 Run、派发、执行窗口和工作区定位，粘贴到任意 Router 会话即可接着提问；不弹出窗口选择框，不填入或发送消息，不依赖 Router 终端绑定（聊天窗口同样可粘贴）。双击只定位窗口，取消待执行的单击。点击标题展开只读会话与往来记录，再次点击收起；面板不提供直接回复，沟通统一通过 Router。重新判断只把“条件可能具备，请重新判断”及 Run/任务/派发标识发送到该 Run 当前真实绑定的 Router 收件箱，不直接驱动执行者、不启动会话。failed 的“交给 Router 重新判断”直接显示在行内，其余位于展开详情；没有真实 Router 绑定时，failed 行按钮禁用，发送前重新核验真实绑定，不使用旧环境文件的 HANDLE。
- 没有停止、删除、释放执行者或修改 Run/任务的接口。
- 刷新每 15 秒进行，隐藏时暂停；切回面板先显示 Orca 按工作区保留的上次列表预览；重新挂载或由不可见恢复可见时立即强制后台更新，不等下一次 15 秒定时点；读取复用最近 15 秒的同查询、同窗口快照，定时与手动刷新强制读取最新数据；一次替换完整列表快照，失败保留上次数据。展开详情单独读取。

读取限制：最近消息窗口为 1000 条；默认最多读取 32 条、显示至多 12000 字；Orca 首次读取返回尾部窗口，cursor 用于继续读取新增输出，并不表示当前窗口是旧页；尾部 32 条内缺少用户输入时只展示最近回复并明确提示本轮不完整。显式执行历史读取最近 50 条原始记录，遵守 Orca 的截断结果。详情显示来源及截断提示，可继续读取后续新增记录。搜索覆盖已载入的 Run，不代表搜索未加载的历史或全量 transcript。

```sh
orca plugin test plugin/osa-panel --json
orca plugin check plugin/osa-panel --json
orca plugin shot local.osa-tasks --width 335 --out /tmp/osa-panel.png --json
```

测试使用模拟 CLI 和剪贴板验证复制引用、定位和 Router 重新判断，不向真实执行者发送内容。单击复制使用当前 macOS 宿主的系统剪贴板。运行时需要已有的 trusted-worker 权限及 workspace:read，只读当前工作区名称、分支和终端列表。列表与组件尺寸受 Orca components API 控制，不保证与内置会话历史像素级一致。

纸笔侧栏图标是所有者授权的唯一 Orca 本体例外：`tools/paper-pen-patch.py` 对当前安装版本的两个 renderer 文件做定点替换并保留备份，可恢复。Orca 更新后需重新核对；当前窗口重载后生效，工具不自动重载。智能体图标取自 Orca 原生 Claude/Codex 资源，PNG 保留透明背景。

待回复计数与“有消息待回”共用同一规则：仅发给 Run/Router 的 question/escalation，并排除 msg_stop_ 及已知系统投递/停止/等待提示回执。Orca 的 status 无可靠人工作者标记，故不凭正文猜测为人工决策请求；任何消息（含未读/未回复）均不维持 Run 活跃。任务自身的 failed/blocked 状态及原始历史依据仍保留。

工单消息按明确 taskId、dispatchId 归属；仅没有这两种标识的旧消息才按关联终端兜底，同一终端的其他工单消息不会混入。

消息区分已送达、已读和已回复：读取或 check 的 handled 不等于解决。同 thread_id（问题无 thread_id 时使用其 id）、时间更晚且收发反向的任意消息均确认已回复，不要求 Re: 主题或 status 类型；现有原生 Router/dispatch 精确地址别名仍可对应。最近 1000 条窗口之外也不能推断已答。面板提醒使用 payload.source=osa-panel，自发给同 Run 的提醒及 queue-scan status 不维持待处理状态。点击重新判断本身不会移除工单，直到 Orca 真实状态或待回复证据发生变化。

“最后更新”优先使用 task.updated_at；缺少时取实际完成、关联消息、当前派发时间的最新值，不以创建时间充当更新。派发时间按 ctx 缓存、分批读取，失败显示警告且不编造时间。所有未回复问题仅在活跃 Run 进入需要你区，死 Run 的问题（含未读）归历史；任何消息都不复活 Run。活跃 Run 的完成工单仍隐藏，仅分组头显示“已完成 N”：按 Run 或真实工作区/项目/智能体归属计数，相同分组跨分区只显示一次，不把没有归属的工单猜到其他工作区。

列表完整数据仅保存在当前面板内存；按工作区持久化的预览保留全部工单、消息标识/状态/时间/关联和完成数量，但缩短正文，详情仍单独读取原始记录。缓存格式升级会丢弃旧缓存。写入前按 Orca 每值 256 KiB 的 UTF-8 上限校验（含版本包装）；即使预览仍超限，也保留已刷新的完整列表、清除旧预览并显式提示，不再静默反复恢复旧状态。

列表读取警告始终可见。展开的工单说明、结果和消息正文最多显示 16000 字，并明确标记截断；原始记录未改动。系统回执标记在原始完整正文上计算后随摘要保留，防止截短后误变成待回复消息。
